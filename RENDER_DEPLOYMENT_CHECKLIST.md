# Render + PostgreSQL test deployment checklist

## Before deploying
- Create a private GitHub repository for this project.
- Upload the project contents with `manage.py`, `requirements.txt`, `render.yaml`, `build.sh`, `newsapp/`, `onps/`, `templates/`, and `static/` at repository root.
- Do not upload `.env`, `.git/` history from another repository, or `database/newspythondb.sql`.
- Review the Render plan and current costs before applying the Blueprint.

## Deploy
1. In Render, choose **New > Blueprint** and connect the repository.
2. Apply `render.yaml`. It defines the Django web service, a PostgreSQL database, and a persistent disk for uploaded media.
3. Wait for build and pre-deploy migrations to complete.
4. Open the Render service URL. If the hostname differs from `news-portal-django.onrender.com`, update `ALLOWED_HOSTS` and `CSRF_TRUSTED_ORIGINS` in the service environment to match the actual hostname.
5. Open the Render Shell and run `python manage.py createsuperuser`.
6. Sign in to `/admin/` and verify the custom dashboard separately. Django superuser status and the application's `user_type` role are different controls.

## Public smoke tests
- Homepage loads over HTTPS.
- Category, article details, and search pages load.
- Anonymous visitors cannot open protected dashboards.
- Login, logout, and password change work.
- Admin can create, edit, and publish news.
- Admin can create an advert with start/end dates, activate/pause it, and confirm the popup appears only during its schedule.
- Image uploads persist after a service restart/redeploy.
- Static CSS, JavaScript, fonts, and images load correctly.
- Social links are configured only with verified publisher-owned destinations.
- Test on mobile and desktop.

## Database warning
The bundled historical SQL file is a MySQL/MariaDB export, not a PostgreSQL backup. Do not import it directly into the Render PostgreSQL database. This deployment starts with an empty PostgreSQL database populated by Django migrations. Historical data migration is a separate task that needs a reviewed conversion/import plan.

## Security before sharing the public URL
- Keep `DEBUG=False`.
- Use a unique production `SECRET_KEY` generated by Render.
- Do not use old or default passwords for test accounts.
- Do not publish database credentials, `.env`, SQL exports, or user password hashes.
- Use test data only until security and permission checks are complete.


## Free test deployment note
The current `render.yaml` requests free web and PostgreSQL plans and does not configure a persistent media disk. Uploaded media may be ephemeral. For reliable image storage, configure S3-compatible object storage or use a paid persistent disk. Verify current Render plan availability and limits before applying the Blueprint.
